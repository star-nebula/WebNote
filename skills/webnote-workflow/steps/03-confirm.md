# 确认（调度器自执行）

> 产出：`runs/<run>/03-待确认提案.md`

> 本文件是操作卡，不是 agent。由**调度器（主会话）**执行，不创建独立上下文。

## 职责

读 `01-笔记` 与 `02-核查表` 两份产出，汇总成待确认提案。**不读原文、不重新核查**——核查已经做完了，你只是汇总。

唯一的新判断是「去向」：这条内容应该落到知识库的哪个类目。这件事必须按**用户自己的分类体系**做，见下一节。

## 条目号（沿用核查表）

提案里所有「条目」列都写 `p<页>-<序>`，与 `02-核查表.md` 完全一致——它是这条链上唯一的锚点，回修与存档都靠它定位。**不要在这里重新编号，也不要只写摘要。**

## 汇总规则

对每条笔记要点给一个建议动作：

| 核查状态 | 建议动作 |
|---|---|
| 已核实（直接引用） | **保留** |
| 已核实（转述源） | **保留（待回看）** —— 建议用户自己核对原始音画后再存入长期库 |
| 可疑 / 原文无依据 | **修正或删除** —— 给出具体理由 |

**所有转述源条目都要单独列出**，不能混在"保留"里一句带过。它们是这份提案里最需要用户注意的部分。

## 值不值得：用笔记匠给的修订建议

核查只管**真假**，不管你用不用得上。判断"值不值得留"的信号只有一个，在 `01-笔记.md` 每条末尾的 `**修订建议**`：值得深读 / 参考写法 / 补充数据 / 可忽略。

| 修订建议 | 怎么处理 |
|---|---|
| 可忽略 | 建议去向写 **不落库**，依据列引原句说明为什么 |
| 值得深读 | 正常给去向 |
| 补充数据 | 正常给去向，但注明"是某个选题的补充材料"，避免以后当成通识入口 |
| 参考写法 | 正常给去向，注明"参考的是写法，不是事实来源" |

去向表的「依据」列**必须引用修订建议里的话**。只写"正文讲的是 X" 不算依据——那只是内容摘要，不是留下它的理由。

## 去哪：按用户自己的分类体系

每个用户对网页内容的分类体系都不同——有人按技术领域分，有人按用途分，有人根本没有体系。本仓**不预设一套类目**，按这个顺序定去向：

| 顺序 | 去哪找 | 怎么用 |
|---|---|---|
| 1 | `AGENTS.local.md` 的「分类体系」段 | 用户自己写的类目表；照用，不增不删、不改名（大小写、空格、标点都照拄） |
| 2 | 知识库现有目录：`<知识库根>/Knowledge/` 与 `Resources/` 下的目录名 | 用户没写体系但目录已存在时，按现有目录名归 |
| 3 | 兜底四类：学习 / 借鉴 / 内容补充 / 可归档 | 前两者都不存在时才用；提案里要标明「这是兜底分类，建议定一套自己的」 |

三条禁令：

- 不发明第 5 个类目，不改写用户目录名
- 拿不准时写「待定 · 需你定类目」，不猜
- 一页只有一个去向；跨两个类目就用主用途那个，另一个在「依据」里注明

## 可疑条目：回修，不交给用户手改

核查官判「可疑」的条目，不要转成"你来改"——那等于让用户替 AI 重写笔记。走**回修**：

1. **只重做被标可疑的部分**：派一次笔记匠（`steps/01-distil.md` 的「回修模式」），输入是 `01-笔记.md` 该页 + `02-核查表.md` 里对应的可疑行 + 原文。
2. **重做后复检**：只核被改动的条目，结果追加进 `02-核查表.md` 同一页，标「复检」。
3. **最多回修两次**。两次之后仍「可疑」，停止回修，在提案里写「已回修两次仍可疑，建议删除」。
4. 回修**只改被标可疑的条目、不许新增条目**——新增内容等于绕过核查。

回修是"改错的"，不是"再写一遍"。整页重做会把已经核过的条目拖回未核状态，是净损失。

## 执行落库（用户点头之后）

提案里的一切都是「建议」。用户逐条点头后，才轮到你真正写。

**只写 `<知识库根>/Resources` 的原始正文，用「标题 + 作者 + 平台」命名。**

```
<知识库根>/Resources/<主题>/<标题> - <作者> - <平台>.md
```

三者缺一不可、顺序固定：标题定内容、作者定归属、平台定来源版本。这样同一篇文章在不同平台的转载、同一作者的不同文章、同名的不同文章都不会撞名。

- 作者：正文署名为准；确实没有署名写 `佚名`
- 平台：公众号 / 知乎 / 掘金 / CSDN / Medium / Apple Podcasts …，取能一眼认出来源的那个名字
- 标题里不能用的字符（`/ \ : * ? " < > |`）换成 `_`；标题超过 60 字截断，完整标题留在笔记首行
- 目标已存在同名文件 → **停下来问**，三个选项：跳过 / 改名（加日期后缀）/ 覆盖。不许自己选，尤其不许覆盖

`<知识库根>/Knowledge` 的知识笔记不适用这条命名——那是知识库自己的结构，按那边的规矩走；那边没规矩时问用户，不要照抄 Resources 的格式。

**写之前**：先写临时文件再 `rename`，避免中途失败留下半个文件。

## 铁律

- 不重新核查原文（核查已经做完了）
- 拿不准时宁可多留一条让用户决定，也不替用户删
- 所有删除、归档、发布、写入长期记录的动作都是**提案**，不自动执行

## 确认边界

判断标准：**这个动作如果错了，撤得回来吗？**

### 必须停在「待确认」

| 动作 | 为什么危险 |
|---|---|
| 删除任何资料、笔记、文件 | 删了找不回来 |
| 归档 / 收起 / 移走 | 眼不见就再也不翻 |
| 发布（发文章、发社交媒体） | 发出去全网看到 |
| 改长期记忆 / 知识库 / 笔记 | 一条假信息进了长期库 |
| 改文件名 / 大批移动文件 | 一动一大片，引用全断 |

### 调度器可以直接做的

- 媒体格式分类、调用提取工具
- 读、归类、提要点、列清单、出提案
- 在临时草稿里改来改去
- 给建议、做对比、标可疑

**一句话：AI 可以无限地"想"和"建议"，但凡要"落地动手"，停在用户这道闸前。**
