# 采编（调度器自执行）

> 产出：`runs/<run>/00-采编清单.md`

> 本文件是操作卡，不是 agent。由**调度器（主会话）**执行，不创建独立上下文。

## 职责

把各种来源的内容变成**可核查的文本**，并记录来源路径。只提取，不生成、不总结、不补充。

## 先查重，再动手

同一条链接进两次，会得到两份互相矛盾的笔记——这直接伤害"可信"。所以采编第一步不是提取，是查：

1. `runs/` 下全部历史运行（含 `_archive/`）的 `00-采编清单.md`，按 URL / 文件名匹配「原文来源」列
2. `<知识库根>/Resources` 下已有文件，按标题 / 来源平台匹配

命中就把结果**列出来问用户**：重采（覆盖旧的）/ 跳过 / 只更新（保留旧笔记，只补新增部分）。**不要自己选。**

同时在 `00-采编清单.md` 的「提取结果」列记一行 `已采过：<run 名 或 库内路径>`，让后面的人看得见这条为什么没重跑。

查不到历史的（新链接、`runs/` 被清过）照常继续，不必额外说明。

## 媒体格式判断（优先级由高到低）

1. **文件扩展名**：路径末尾（不含查询参数）以 `.pdf/.docx/.pptx/.xlsx` 结尾 → **文档**
2. **域名 + 路径模式**：
   - 音频：`music.163.com`、`music.youtube.com`、`spotify.com`、`xiaoyuzhoufm.com`、`podcasts.apple.com`
   - 视频：`youtube.com/watch`、`youtu.be`、`bilibili.com/video`、`b23.tv`、`douyin.com`、`kuaishou.com`、`v.qq.com`、`v.youku.com`、`iqiyi.com`
   - 图文：`mp.weixin.qq.com`、`zhuanlan.zhihu.com`、`blog.csdn.net`、`juejin.cn`、`oschina.net`、`segmentfault.com`、`medium.com`
3. **路径模式**：含 `/article/`、`/posts/`、`/blog/` 等 → **图文**
4. **都判断不了** → 标「无法判断」，**问用户**，不硬猜

## 路由：判断完加载对应的分支卡

| 判断结果 | 处理方式 | 分支卡 |
|---|---|---|
| 图文（已有正文） | 直接使用，不调工具 | — |
| 图文（正文为空） | `extract-webpage.py <URL>`（bsk 优先，失败自动走静态 HTTP） | — |
| 文档 | `extract-document.py <文件路径>` | — |
| 图片 | OCR →（可选）Vision | [branches/image.md](branches/image.md) |
| 视频 / 音频 | 页面文本 → ASR → 画面 | [branches/video-audio.md](branches/video-audio.md) |
| 防复制页 / 云文档 / 登录墙长文 | PowerShell + Chrome 链无损拓存 | [branches/web-archive.md](branches/web-archive.md) |
| 无法判断 | `extract-webpage.py <URL>` 尽力读取 | — |

**只加载命中的分支卡。** 处理一个 PDF 时不需要知道 ASR 怎么跑。

## 「有正文」怎么判（这一列由本步负责）

`有正文` 是下游唯一的分流依据——`01-distil` 只处理标「有」的条目，`02-verify` 据它判可信度上限。判据必须留在这张卡里，不能留给下游临场决定（它曾经在别处，删那一步时一起丢了，于是谁都能自己定）。

按 `正文字符数` 判：

| 正文字符数 | `有正文` 记什么 | 含义 |
|---|---|---|
| ≥ 200 | `有` | 正常，后续按笔记标注的来源类型判可信度 |
| 50–199 | `有（疑截断）` | 抓到了，但大概率只有首屏 / 导读 / 付费墙前段 |
| < 50 | `无` | 装不下任何内容，只剩标题或一句导语 |

`有（疑截断）` 说的是**提取可能是残片**，不是"内容短"：

- `02-verify` 对这类页面的条目**一律按「转述源」封顶**，即使笔记标的是「原文」——你核到的只是"笔记忠实反映了这份残片"。
- `01-distil` 只许提炼残片里确实说过的内容，**不许从标题或常识补**。
- 判不出来时（渲染后文字是图片、登录墙后全空）记 `无`，并在「提取结果」列写清原因（登录墙 / 只出图 / 空）。

## 工具输出格式

统一 JSON 到 stdout，取 `text` 字段：

```json
{"success": true, "text": "...", "char_count": 1234, "method": "pypdf|bsk-webpage|static-http|bsk-video|faster-whisper-small|video-frames-rapid+ds-vision", "error": null}
```

`extract-video-frames.py` 另输出 `per_frame[]`（每帧 `file / t / ocr_text / vision_text`）。

## 铁律

- 通过 `bsk`（BrowserSkill）操作**用户已登录的浏览器**读取页面，不发起未经认证的 HTTP 请求
- 只提取已有文本，不生成、不总结、不补充
- 提取失败如实标「无法提取」，不硬凑
- `DEEPSEEK_API_KEY` 只走环境变量，不进代码、不进 git
- 原文**只读**，不复制、不移动

## 输出 → `runs/<run>/00-采编清单.md`

```markdown
# 00-采编清单

> 生成时间：<日期>
> 执行者：调度器（主会话）
> 运行模式：模式 A / 模式 B

## 内容清单

> 正文副本在 `runs/<run>/原文/<ID>.txt`（文件名用 `<ID>.txt`：条目号 `p01-1` 以它为锚，标题记在清单里；`runs/` 之外落库时用标题命名，见 `AGENTS.local.md`），一个条目一个文件。

| ID | 标题 | 域名 | 媒体格式 | 正文字符数 | 有正文 | 提取方式 | 提取结果 | 原文来源 |
|----|------|------|---------|-----------|--------|---------|---------|---------|
| p01 | ... | ... | 图文 | 807 | 有 | 直接使用剪藏正文 | 成功 | `<路径>` |

## 逐条采编说明

### p01 · <标题>
- 来源类型：<...>
- 处理方式：<...>
- 内容要点：<一句话概括，供笔记匠参考>

## 有正文统计（供 01-笔记 使用）

- 有正文：N 条
- 有（疑截断）：K 条
- 无正文：M 条

## 运行异常

- <哪一步 · 什么现象 · 当时怎么处理的>（无异常写「无」）
```

**清单只记元信息；正文本体另存一份副本。**

每个条目提取完，把拿到的正文原样写到 `runs/<run>/原文/<ID>.txt`（一个条目一个文件，纯文本，不做任何加工）。「原文来源」列只记出处（URL / 文件路径），**它是标签，不是读取指令**。

为什么要这份副本：网页的"原文"是活的。页面改版、付费墙收紧、登录态过期、内容被删，都会让核查官看到与笔记匠不同的东西——那时判「可疑」，删掉的是无辜条目。三态判定的全部价值，建立在**两个人看的是同一份字节**上。有了这份副本，提炼与核查都只读它，不重抓；跑完之后也能回答"AI 当时到底看到了什么"——这是排查编造类问题的唯一原始证据。

`runs/` 整目录不进 git，这份副本只占本地磁盘。

「提取方式」为 `bsk`/OCR/ASR/Vision 时，副本里存的就是那些工具的 `text` 输出，`有正文` 按副本字符数判。

## 运行异常：这是改进流程的唯一入口

运行中出错的地方写进这一节，**不要只在对话里吐槽**：工具报错、参数踩坑、人工补救、绕过的步骤、预期外的时间与 token 消耗。

- 有异常就逐条写清「哪一步 · 什么现象 · 当时怎么处理的」，没有就写「无」。
- 这一节留给**过程**，不写结论：值不值得改流程，看它出现几次。
- 同一异常**第二次**出现时，必须升级——变成一条测试（首选，红了就非修不可）或一条 `docs/decisions.md`，而不是继续堆在这里。

判据：写在这里的东西，下一次运行的人（可能是你自己）会读到；写进别处的，就没人读了。
