# memory/ · 长期记忆

**这里只放跨 run 提炼出来的结论**，不放原始过程（原始过程在 `runs/`，那是过程不是记忆）。

## 什么时候读

- 开工前：读 `core` 段（在 `AGENTS.md`，不用读这里）+ 扫一眼 `index.md`，只挑与本次内容相关的条目读全文。
- 收尾时：有新结论要沉淀 → 写一条 `long-term/<YYYY-MM-DD>-<slug>.md`，在 `index.md` 加一行。

## 什么时候**不**读

- 不要整目录读。一条一文件就是为了让你只读需要的那条。
- 不要靠记忆里的旧结论代替当前原文证据——记忆是经验，不是证据。

## 谁能写

- 只有调度器（主会话）在用户确认之后写。角色（classifier / distiller / verifier）**一律不写记忆**：核查官更不许把自己的判断沉淀成"以后都这样"。
- 落地前必须给 `04-待确认提案.md`，用户点头才落盘（第三条铁律同样管记忆）。

## 一条记忆的格式

```yaml
---
date: 2026-11-09
topic: 提取
confidence: confirmed   # confirmed | tentative
source: runs/2026-11-09-xxx/03-核查表.md
---
```

正文三行以内说清：**当时遇到什么 → 结论是什么 → 什么条件下才适用**。
`confidence: tentative` 的条目在被第二次验证前，不得当依据用。

## 与知识库的分工

| 放哪 | 放什么 | 谁读 |
|---|---|---|
| 本目录 `long-term/` | 这个 bot 干活时攒下的经验、踩坑、用户确认过的偏好 | agent |
| `<知识库根>/Projects/WebNote/Project.md` | 项目现在什么状态、待定事项、决策链接 | 人 + agent |
| `<知识库根>/Resources/`、`<知识库根>/Knowledge/` | 提取出来的**内容本身** | Obsidian |

同一条结论不写两遍：仓内记「下次怎么做得对」，知识库记「这次产出了什么」。
